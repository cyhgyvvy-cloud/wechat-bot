# 微信群 AI 机器人（Windows）

一个跑在 Windows 微信桌面端上的个人助手机器人。接入任意 OpenAI 兼容接口，能读群聊和私聊、按人设回话、发表情包、发真·语音，也会在没人说话的时候自己开口。

> 纯桌面端自动化方案，依赖 UI 操作，不适合无人值守的生产环境。请只在你自己的账号和群里使用。

## 功能

| 功能 | 说明 |
|---|---|
| 群聊回复 | `trigger` 支持 `all`（每条都回）/ `mention`（仅 @）/ `prefix`（前缀匹配） |
| 私聊回复 | 白名单制，`private_chats` 里填昵称或备注名，精确匹配 |
| 人设 | `persona.txt` 写角色设定，改完下一条消息生效 |
| 表情包 | 从本地图库按分类随机配图，也可在你明确要求时必发；实测约 1 秒落库 |
| 识图 | 收到的表情包 / 照片会先交给模型识别再回应，读不到时可以选择如实说 |
| 语音回复 | 合成 → 播到虚拟声卡 → 按快捷键让微信录音 → 松开发送，全链路自己实现，**不依赖任何外部语音程序** |
| 主动发消息 | 按时间段、间隔、额度、会话安静度、键鼠空闲度五道闸门，自己挑个会话开口 |
| 记忆 | 每个会话的对话落盘，重启接着聊；模型自己总结「谁喜欢什么、约过什么」，回答前按相关度回忆 |
| 后台运行 | `manager.ps1` 管进程，PID 落盘、日志分离、重复启动会被拒绝 |

## 环境要求

- Windows 10 / 11（64 位）
- Python 3.11（64 位）
- 已登录的微信桌面版
- 语音功能另外需要：[VB-CABLE](https://vb-audio.com/Cable/) 虚拟声卡

## 快速开始

```powershell
git clone <本仓库地址>
cd <仓库目录>

# 1. 复制配置模板
copy config.example.json config.json

# 2. 安装依赖（或直接双击 install_env.bat）
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 3. 填入 API Key（DPAPI 加密存到 secret.txt）
右键 设置密钥.ps1 → 使用 PowerShell 运行
```

4. 编辑 `config.json`，至少改这几项：

   | 字段 | 说明 |
   |---|---|
   | `base_url` | API 根地址，**不要**带 `/chat/completions`，程序自动拼接 |
   | `model` | 服务商给的模型 ID |
   | `group_name` | 目标群名，必须与微信里**完全一致** |
   | `bot_name` | 机器人在群里的昵称（`mention` 模式必需） |
   | `private_chats` | 允许私聊的好友备注名列表，留空 = 不接私聊 |

   `private_chats` 不确定该填什么时，直接双击 `list-private.bat`：它连上当前登录的微信，
   把最近的私聊会话列到 `list-private.txt`，并标出哪些名字已在名单里、哪些可以直接加。
   注意**有备注的联系人必须填备注名**，填原始昵称匹配不上。

5. 打开微信，把目标群置于会话列表第一位、输入框不留草稿，然后双击 `启动后台.vbs`。

停止用 `停止后台.vbs`，看状态用 `查看状态.bat`。

## 语音功能

语音是本项目里唯一需要额外配置的部分，但整个链路由程序自己完成，不依赖任何外部程序：

```
文本 → TTS 接口合成 wav → miniaudio 播到 CABLE Input
     → 按下录音热键 → 播放 → 松开 → 微信自动发送
```

需要三样东西：

1. **VB-CABLE 虚拟声卡**。安装后到「声音设置」把**默认录音设备**设为 `CABLE Output`，播放仍留在扬声器。
2. **TTS 密钥** `breeze.key`，按机器 + 用户加密，换机器必须重新生成：
   ```powershell
   python gen_voice_key.py brz_你的密钥      # 直接写入
   python gen_voice_key.py                   # 或从旧版程序的密钥迁移
   ```
3. **微信「按住说话」快捷键**设为 `Ctrl+Tab`（设置 → 快捷按键）。这一项存在微信自己的配置里，任何备份都带不走。

装好先跑一次离线自检，它不碰微信，只验证「合成 → 解码 → 播到指定设备」：

```powershell
python voice_native.py
```

看到 `SELFTEST_OK` 就说明音频链路通了。

> ⚠️ 最常见的问题是**气泡正常但点开完全没声音**。原因是虚拟声卡装过多次会留下 `2-`、`3-` 前缀的重复设备，它们是彼此独立的线。必须让播放和录音指向同一组、不带前缀的那对。这个错误日志里一个字都不会报。

## 记忆

两层，都存在本地 `cache/memory.db`（SQLite），不上传任何地方：

| 层 | 存什么 | 作用 |
|---|---|---|
| 会话历史 | 每个会话最近 `keep_messages` 条对话（默认 60） | 重启后接着聊，不会一重启就「你说过什么来着」 |
| 长期事实 | 模型自己总结的短句，谁 + 什么事（每个会话上限 `max_facts` 条） | 回答前按相关度取回，接得住「你还记得我不吃甜的吗」 |

长期记忆的写法是**模型自己整理**的：每攒够 `extract_every` 条消息（默认 16），
在后台线程里把最近的对话交给模型，让它挑出「值得以后记住的事」——身份与称呼、
稳定偏好、约定与计划、重要经历。寒暄、一次性情绪、隐私信息（手机号、住址、密码）
明确要求不记。两次整理之间至少隔 `extract_min_gap` 秒（默认 180），所以正常聊天
大概十几分钟才多一次调用。

回忆是**按关键字相关度**取的：中文按两字窗口 + 单字兜底匹配，一个词都不沾边的记忆
不会塞进 prompt，宁可少一条也不让模型顺着无关记忆跑偏。命中后 `uses` 计数 +1。

```json
"memory": {
  "enabled": true,
  "db": "cache/memory.db",
  "keep_messages": 60,
  "max_facts": 120,
  "recall_limit": 6,
  "extract_every": 16,
  "extract_min_gap": 180
}
```

程序版直接在控制台「记忆」页看：可按会话筛、按关键字搜、单条删除、按会话或全部清空。
源码版也能用命令行：

```bash
python memstore.py stats          # 有多少条记忆/历史，分别在哪些会话
python memstore.py list 群名       # 列出某个会话记住了什么
python memstore.py clear 群名      # 清空某个会话（不带参数 = 全清）
```

记忆写入全程 `try/except` 吞异常：库坏了、盘满了，最多丢一条记忆，不影响回消息。

## 目录结构

```
bot.py              监听、模型请求、发送调度（主程序）
voice.py            语音分发层，按 voice.engine 选实现
voice_native.py     独立语音引擎：TTS + 播放 + 热键（默认），可直接运行做自检
proactive.py        主动发消息：选目标、闸门、上下文、相似度去重
sticker.py          表情包发送
memstore.py         记忆：历史落盘 + 长期事实（SQLite，cache/memory.db）
vision.py           识图
manager.ps1         进程管理（启动/停止/状态）
set_engine.py       切换语音引擎
gen_voice_key.py    生成 / 迁移 TTS 密钥
list_private.py     列出私聊会话，辅助填写 private_chats
install_env.bat     建虚拟环境并装依赖
设置密钥.ps1        安全输入 API Key
persona.txt         角色提示词
config.example.json 配置模板
使用说明.txt         完整的配置项与排错手册 ← 遇到问题先看这里
教程-从零安装.md     从空机器开始装一遍的完整记录
```

`diag_*.py` 是几个诊断脚本，机器人不工作时可以单独跑，用来判断卡在监听、语音还是表情包。

## 安全须知

以下文件**按设计不会**进入版本库（见 `.gitignore`），也请不要手动提交：

| 文件 | 原因 |
|---|---|
| `secret.txt` | 模型 API Key，DPAPI 加密 |
| `breeze.key` | TTS 密钥，DPAPI 加密 |
| `config.json` | 含真实群名、好友昵称、本机路径 |
| `.account_cache.json` | 含微信 wxid 与本机数据目录 |
| `cache/`、`*.log` | 聊天上下文、运行日志 |

DPAPI 加密绑定「机器 + Windows 账户」，所以这两个密钥**复制到别的机器上无法解密**。换机器时重新生成，不要拷贝。

## 已知限制

- **拿不到发送回执**。日志里的 `sent_unconfirmed` 表示「已执行完发送动作但无法确认气泡出现」，不等于失败。
- **会抢焦点**。发送依赖 UI 自动化，过程中可能切换窗口、短暂占用键鼠。不适合需要全程安静操作的环境。
- **需要前台可见**。微信窗口被最小化或被完全遮挡时，发送会超时。
- **微信版本敏感**。依赖第三方自动化库，微信大版本更新可能导致失效。
- **可能触发平台限制**。请自行评估风险，遵守微信的规则。
